## Goal
A restaurant that pays monthly by card keeps a `subscription` record. Each PayFast monthly charge (the first one and every later one) updates it. A failed charge starts a 7 day grace. When the grace ends and the payment is still not fixed, campaigns pause: creating a new campaign is refused and scheduled campaigns do not send. Nothing else ever stops (till, stamps, redemptions, the guest card, the wheel, the owner screens). Paying again turns everything back on by itself. Restaurants on the invoiced plan are covered too: an invoice that is open more than 7 days after its due date pauses campaigns the same way.

## Build
### 1. Database (migration 0038)
- Table `subscription`: `restaurant_id uuid primary key references restaurant(id) on delete cascade, plan plan_tier not null, state text not null check (state in ('active','past_due','cancelled')), provider_token text, last_paid_at timestamptz, next_due_at timestamptz, past_due_since timestamptz, grace_ends_at timestamptz, updated_at timestamptz not null default now()`. Row level security enabled and forced. A tenant read policy so an owner or manager reads only their own row (`restaurant_id = app_restaurant()`), an operator policy for all. `grant select on subscription to app_user` only (no insert, update or delete grants).
- Table `subscription_charge` (one row per PayFast notice so a repeated notice never counts twice): `provider_ref text primary key, restaurant_id uuid not null references restaurant(id) on delete cascade, payment_id uuid not null references payment(id), outcome text not null check (outcome in ('paid','failed')), amount_cents integer not null, created_at timestamptz not null default now()`. Row level security enabled and forced, NO grants to `app_user` (only SECURITY DEFINER functions touch it).
- `billing_paused(p_restaurant uuid) returns boolean` (SECURITY DEFINER, `stable`, `set search_path = public, pg_temp`, helper: `revoke all ... from public`, do NOT grant to app_user). It is true when any of: the subscription is `past_due` and `grace_ends_at < now()`; the subscription is `cancelled` and `next_due_at < now()`; an invoice of the restaurant is `open` and `due_date + 7 < current_date`. It must read the tables with `app.is_operator` set to true and restore it (same pattern as the other definer functions).
- `drop function settle_card_payment(uuid, integer, text, text);` then create it again with a fifth parameter `p_token text default null` (same name, same return type text), same `revoke ... from public` and `grant execute ... to app_user`. Keep EVERY existing rule exactly: the first line refuses any call that has a restaurant or guest context (`not_allowed`), `bad_outcome`, `payment_not_found`, `amount_mismatch`, the row lock, top ups unchanged, `restaurant.plan` is set only from the stored `p.plan`. New behaviour only for `p.kind = 'subscription'`:
  - First paid notice (payment not yet `paid`): do what it does today, then insert the `subscription` row (state `active`, `last_paid_at = now()`, `next_due_at = now() + interval '1 month'`, `provider_token = p_token`, plan from `p.plan`) with `on conflict (restaurant_id) do update`, and insert a `subscription_charge` row for `p_provider_ref` (skip this when `p_provider_ref` is null or empty). Return `paid`.
  - A notice for a subscription payment that is already `paid` is a RENEWAL (or a repeat). If `p_provider_ref` is null or empty, or a `subscription_charge` row with that ref already exists, return `already_paid` and change nothing. Otherwise:
    - outcome `paid`: the amount must equal `p.amount_cents` (else `amount_mismatch`); insert the charge row `paid`; set the subscription `active`, `last_paid_at = now()`, `next_due_at = now() + interval '1 month'`, `past_due_since = null`, `grace_ends_at = null`; audit `subscription_renewed`; return `renewed`.
    - outcome `failed`: insert the charge row `failed`; set `state = 'past_due'`; if it was not already past due set `past_due_since = now()` and `grace_ends_at = now() + interval '7 days'`; if it already was past due keep both dates (a second failure does not extend the grace); audit `subscription_payment_failed`; return `past_due`.
    - outcome `cancelled`: set `state = 'cancelled'` (keep `next_due_at`); audit `subscription_cancelled`; return `cancelled`. Do not change the plan.
  - Notices that arrive for a payment whose first notice has not been settled yet and whose outcome is failed or cancelled keep the old behaviour (`ignored`).
- `find_subscription_payment(p_token text) returns uuid` (SECURITY DEFINER, same search_path, refuses any call that has a restaurant or guest context with `not_allowed`, granted to `app_user`): returns the id of the `kind = 'subscription'` payment that belongs to the subscription with that `provider_token`, or null. The webhook uses it when `m_payment_id` is missing or unknown.
- `create or replace function create_campaign(...)`: copy the whole latest body from `0033_sending_finish_dev.sql` unchanged and add one rule right after the caller and restaurant checks: `if billing_paused(p_restaurant) then raise exception 'billing_paused'; end if;`. Same signature, same grants.
- `create or replace function claim_due_campaigns(...)`: copy the body from `0027_sending_dev.sql` and add `and not billing_paused(c.restaurant_id)` to the `due` selection so paused restaurants' campaigns stay `scheduled` and go out after they pay.
- `operator_set_subscription_state(p_operator_id text, p_restaurant_id uuid, p_state text, p_note text) returns void` (guard with `assert_operator` first, save and restore operator like `0029`): state `active` or `cancelled`; note 3 to 300 characters. `active` sets `last_paid_at = now()`, `next_due_at = now() + interval '1 month'`, clears the past due dates (used when Karma receives the money by EFT). Creates the row if it does not exist (needs the restaurant's current plan). Audit `subscription_set_by_operator`.
- Extend `operator_restaurant_detail` from D23 (migration `0036`): `create or replace` it with a new key `subscription` (state, plan, last_paid_at, next_due_at, grace_ends_at, paused boolean from `billing_paused`). Copy the existing body from `0036` and only add the key.
